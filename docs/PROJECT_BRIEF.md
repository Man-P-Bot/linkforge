\## 8. 关键实现约定

\### 短码生成

> ⚠️ **本条已被推翻（2026 前期文档阶段）**：雪花 ID 的 Base62 表示约 11 位，**压不到 7 位**；强行截断在 1000 万量级下碰撞概率接近 100%。
> 现行方案见 `docs/DECISIONS.md` **DR-011**：**发号器（Redis INCR / 数据库号段）→ Base62 → 固定 7 位**，唯一索引降为兜底。
> 原文保留如下，仅作历史记录，**不再作为实现依据**。

\- 雪花 ID → Base62 → 6\~8 位字符串

\- 加 1\~2 位随机盐

\- 数据库 short\_code 唯一索引，冲突重试



\### 跳转缓存流程

1\. 布隆过滤器判断短码是否存在，不存在直接 404

2\. 查 Redis，命中直接 302

3\. 未命中查 MySQL，存在则回填 Redis，TTL 1 小时 + 随机 0\~5 分钟

4\. 不存在则缓存空值 30 秒，防穿透

5\. 返回 302



\### Redis Key 设计

\- shortlink:code:{shortCode} → 原始 URL

\- shortlink:bloom → 布隆过滤器

\- shortlink:stats:{shortCode}:{date} → PV 计数

\- shortlink:limit:{ip} → 限流计数



\### 限流

\- Redis + Lua 做令牌桶或滑动窗口

\- 按 IP 限流，如每秒 20 次

\- 也可用 Redisson RRateLimiter



\### 异步统计

\- 跳转时 INCR

\- 定时任务每 10 秒批量写 MySQL

\- 跳转链路不碰数据库写



\## 9. 压测目标

\- 单机 QPS：从 2k 优化到 5k\~1w

\- P99 < 50ms

\- 缓存命中率 > 95%

\- 数据库写入压力降低 80%

\## 12. Git 规范

1\. 项目使用 Git 管理，每个可运行、可验证的小节点提交一次。

2\. 提交前必须确保：编译通过、相关测试通过、服务能启动。

3\. 提交信息用 Conventional Commits：<type>(<scope>): <描述>。

&#x20;  type 用 feat/fix/docs/refactor/test/chore/perf。

4\. 较大功能开 feature 分支，完成后合回 main；小改动直接提交 main。

5\. 每次提交后汇报 commit hash 和提交信息。

6\. 出错回退优先级：

&#x20;  - 只改了一部分：git restore <file> 或 git checkout -- <file>

&#x20;  - 已提交但想撤销：git revert <hash>（保留历史）

&#x20;  - 未提交的临时改动：git stash

&#x20;  - 不要用 git reset --hard 除非我明确同意

7\. 不要提交：target/、.idea/、\*.iml、本地配置文件、密码、.env。

8\. 第一次提交前先生成 .gitignore。

9\. 不要执行 git push --force。

10\. 每次开始新阶段前，先 git status 确认工作区干净。
